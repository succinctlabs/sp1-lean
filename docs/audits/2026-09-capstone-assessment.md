# Consolidation assessment

Assessment date: 2026-09-08. This records a review of the eight unmerged pull requests and the
repairs made while preparing a single development for external review. It is a reproducible
baseline and a scope decision aid, not an independent certification of the entire development.

The subsequent accepted target is a self-contained native Clean soundness/completeness capstone,
including constrained inline host effects and whole-ensemble Rust export. The choices below record
the original assessment; current implementation status and remaining proofs are maintained in
the [roadmap](../roadmap.md#native-clean-core).

The stack already has one combined tip. Its instruction verification, native grounding, and
ordinary-shard compiler form a substantial closed development, with explicit restrictions.
Full exact-Core soundness is still a separate proof project. Active syscall support also needs
more than registering the newly proved chip. A useful handoff can be made at the current theorem
boundary, provided these distinctions remain visible and the remaining review is completed.

## Confirmed defects and dispositions

### Lint failure in the syscall trace-table API

`SyscallInstrsChip.traceTable_table` was marked `[simp]`, but existing simplifications already
reduce its left-hand side. The baseline `simpNF` linter rejected it. Removing only the redundant
attribute preserves its name, proposition, and proof. Its known callers invoke it explicitly.
No circuit, witness generator, or semantic predicate changed.

### Axiom inventory could silently lose a renamed theorem

Some generator targets use regular-expression alternatives. If one theorem is renamed beyond the
pattern while another still matches, the existing nonempty-target check passes and the missing
probe disappears. Earlier repairs restored two `_core` probes but did not prevent recurrence.

A regression reproduced this failure against the original generator. Generation now checks both
recorded inventories before writing either file and rejects lost declarations. `--check` is
read-only and runs in CI. Intentional removals require `--allow-removals` and review of the probe
diff. Seven regressions cover partial matches, both library files, intentional renames, and
read-only checks. The existing generated probes and raw axiom snapshots remain unchanged.
The [historical ledger](https://github.com/dtumad/sp1-lean/blob/6428cd45/docs/snapshots/axiom-ledger.md)
records the census approach's coverage limits. The current replacement is described in the
[trust policy](../trust-policy.md).

### Current documentation described incompatible theorem versions

The source and public documents mixed table counts, channel counts, a two-conjunct native relation,
an ordinary-only conclusion, and the later HALT/syscall development. Some completeness prose still
said shared relation alignment was open after it had been proved. The README and overview now
describe the current boundary; corresponding report, architecture, release-audit, contributor, and
source comments are corrected. The ledger's campaign history is replaced by the current inventory
contract, with history retained in git.

There are 55 native tables and seven channels. `SupportedCoreNativeRelation` has three conjuncts:
ensemble validity, semantic boundary binding, and `SyscallTableInactive`. Its conclusion admits an
ordinary run or an ordinary prefix followed by modeled HALT. The deterministic completeness
compiler still emits a padding Halt row and an empty SyscallInstrs table.

### Canonical syscall words are a stronger profile than Rust dispatch

`CoreSyscallEvent.IsInlineCanonical` tests the whole 64-bit word against the inline syscall IDs.
The pinned Rust executor reads the register as a 64-bit value but dispatches through
`SyscallCode::from_u32(syscall_id as u32)` (`crates/core/executor/src/vm.rs`, the ECALL path).
Thus `0x100000003` dispatches as code `3` while failing the native full-word predicate.

The earlier statement that this predicate holds for every genuine Rust execution was too strong.
It is now disclosed as a native profile restriction. This observation is a dispatch-level
counterexample to that explanation, **not** a constructed whole-AIR counterexample. Whether to
retain the profile or widen the semantics needs an explicit compatibility decision and a complete
AIR/ROM/host analysis. No predicate was weakened during this assessment.

## What the closed theorems assume

| Claim | Load-bearing inputs and exclusions |
|---|---|
| Instruction soundness and completeness | The per-chip semantic contracts and caller assumptions; reader/program/memory meaning is supplied through grounding and providers. The 25 routes cover the supported instruction profile. |
| Instruction Rust faithfulness | Complete constraints and active interaction permutations on the native row reconstructed by each codec. This is not a quantification over arbitrary native assignments outside that image. |
| `supported_core_native_sound` | Clean constraints and balance; program/provider and initial-state semantic binding; inactive SyscallInstrs table and physically present Halt table. It does not derive the semantic boundary from the exact upstream system tables. |
| `supported_core_boot_to_halt_single_shard` | The native relation plus the explicit boot boundary and live Halt conditions. No joint boot-to-live-Halt inhabitant has been constructed. |
| Native functional completeness | Ordinary semantic execution, compiler readiness and physical footprint bounds. `NativeTraceReady` includes zero exit, syscall freedom, event/row agreement, memory genesis, and provider readiness. |
| Native correctness and language equality | Conditional on `NativeShardTraceTotal` for the shared bounded ordinary semantic relation. This condition is not instantiated. |
| Exact-to-native local artifact | Valid paired exact clusters plus preprocessing, public-limb, and memory-boundary contracts. It manufactures padding Halt and empty SyscallInstrs tables. Global State/Memory/Exit balance, count bounds, and semantic binding remain explicit. |
| Exact-Core soundness combinators | A caller-supplied `CoreAIRRefinementObligations` bundle and external loader/platform context. The source is an exact natural-multiplicity AIR relation, not cryptographic verifier acceptance. |

The native instruction library is field-generic. The exact system layer contains KoalaBear-specific
constants. The generated Sail target still has external platform hooks and assumes configured
initial state, loaded code, and code/memory compatibility. Axiom cleanliness does not discharge any
of these semantic premises.

## Remaining proof work and dependencies

### Terminal HALT and ordinary completeness

The shared ordinary relation and row-limit policy already exist. Proving `NativeShardTraceTotal`
still requires deriving readiness and the actual physical interaction footprint from that source.
Terminal HALT is a separate extension: compiler occurrences currently have no active Halt case,
and readiness requires zero exit. A concrete joint boot/HALT witness would establish a useful
non-vacuity result even before general HALT completeness. These should be scoped separately.

The existing active regression is stronger than a hand-assembled row check: it joins an official
Sail self-jump, its deterministic compiler event, a nonempty bounded native witness, and soundness
back into the shared semantic relation. It does not inhabit the boot/HALT relation.

### Active inline syscalls

The full SyscallInstrs chip has local semantic and faithfulness proofs, and the mixed event relation
is defined. The mixed Memory ledger machinery includes refresh elimination and balance lemmas.
The witness-specific grounding construction and a capstone producing `SupportedCoreEventRelation`
are still missing.

Its faithfulness theorem is factored: extracted assertions correspond to native constraints
**and `PublicValueBinding`**; native interactions correspond to Rust interactions plus native
public-value messages. Those messages encode the exit code, COMMIT flags, and selected digest
cells. The ensemble has no authenticated PublicValues provider yet. Exit already has the verifier
pull and Halt producer, but needs a terminal-row policy that accepts the full syscall path.
Deleting `SyscallTableInactive` alone therefore cannot complete this integration.

The canonical syscall-word profile and the inline host handler also need review against the pinned
executor. Inline semantics do not implement all Core/precompile handlers. Active syscall compiler
support and end-to-end regressions would then need to accompany the soundness extension.

### Exact Core AIR refinement

`CoreAIRRefinementObligations` names twelve fields: `publicValuesWellFormed`,
`firstExecutionShard`, `syscallTranscript`, `publicCommitOperand`, `deferredCommitOperand`,
`publicCommitSetsFlag`, `deferredCommitSetsFlag`, `commitTransition`, `memoryWellFormed`,
`memoryAgrees`, `boundaryCase`, and `executionCase`. Supporting results exist, including some
restricted syscall-free consequences, but there is no closed construction of this bundle.

Closing it requires authenticating preprocessing and program identity, interpreting the exact
system tables, connecting raw Global data to typed Memory, handling Range-width transport,
proving the remaining native integer balance and count bounds, and constructing execution from
the exact witness. Syscall transcript and host-profile work must agree with that construction.
The external decode/loader/platform context remains a separate explicit boundary.

Cross-shard execution and cryptographic verifier knowledge soundness are further workstreams.
A deterministic theorem from verifier acceptance to execution would additionally need extraction
assumptions and the cryptographic error bound; none is supplied by this native development.

## Finish-line choices

| Finish line | Additional work beyond consolidation and review | Relative scope |
|---|---|---|
| Reviewed current theorem boundary | Complete the semantic/assumption review, maintainability cleanup, and reviewer handoff; retain explicit incomplete integrations | Bounded; recommended for a handoff without a new proof campaign |
| Current boundary plus concrete boot/HALT non-vacuity | Construct and check a joint inhabitant; state separately whether general terminal-HALT compilation is included | Focused proof extension, with witness-construction uncertainty |
| Active canonical inline syscalls | Mixed grounding, authenticated public values, terminal policy, agreed opcode profile, compiler and active regressions | Substantial integration across semantics, ensemble, and completeness |
| Closed exact-Core refinement for an agreed supported profile | System-table semantics and all applicable refinement fields, plus compatible event/host integration | Largest scope; cannot be estimated as a final wrapper lemma |

The recommended default is the reviewed current boundary. It preserves the existing mathematical
work as a coherent result while making the remaining obligations reviewable. The other options
should be chosen as explicit theorem targets, with precise profiles and acceptance examples,
before broad proof implementation begins.

## Review coverage and remaining handoff work

This pass checked the ancestry, build and generation boundaries, released inventory, all 25
instruction semantic `Spec` surfaces, and the headline soundness/completeness/exact-refinement
premises. It examined the syscall faithfulness/public-value split and compared canonical dispatch
with the pinned Rust executor. It repaired the confirmed tooling and documentation defects above.

It did not perform a line-by-line independent proof/spec review of every module, exhaustively
audit the Rust exporter or generated Sail source, or construct adversarial full-AIR witnesses.
Successful kernel checking is evidence about the stated propositions, not evidence that every
statement captures the intended SP1 behavior. Further findings remain possible.

After choosing the finish line, the remaining consolidation work is to open the replacement draft
PR, complete review against that claim, finish removing plan-number language and obsolete
scaffolding with consumer checks, and provide a maintainer-oriented contribution/reproduction
guide. Existing review attribution and immutable provenance should survive that cleanup. The old
PRs can then be marked superseded by the reviewable replacement while preserving their history.

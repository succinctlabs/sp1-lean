When proving `¬(x = y)` in a Compare/Lt chip where the constraints include `not_eq_inv * (x - y) = 1` (the standard uniqueness witness for "x ≠ y"), the idiomatic close after introducing `eqc : x = y` via `intros; rename_i eqc` is:

```lean
rw [eqc] at lt_07
simp only [sub_self, mul_zero] at lt_07
exact absurd lt_07 (by decide)
```

**Why:** `not_eq_inv * 0 = 0` in `Fin KB`, and `(0 : Fin KB) ≠ 1` is decidable. `simp_all` is too aggressive here — it can substitute the `not_eq_inv` equation backwards and create weird forms. `simp only` is the right granularity.

**How to apply:** Use in the last branch of a `first | … | …` closer inside `rcases b_msb_b <;> rcases b_msb_d <;> simp_all` pipelines when handling the `refine_1 : ¬b[i] = d[i]` sub-goals generated by `split_ands` in `spec.branch`-style proofs. For the remaining `b[i] = d[i]` goals in all-zero-flag mixed-msb cases, use `intros; subst_vars; grind` (per `feedback_grind_ring_finkb.md`) as the trailing fallback.

See `LtOperationSigned.spec.branch` (signed branch, `SP1Operations/Compare/LtOperationSigned.lean:166–188`) for the canonical pattern.

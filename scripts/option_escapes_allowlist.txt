# Allowlist for elaboration-budget escape hatches — enforced by scripts/check_option_escapes.sh.
#
# Format:  <option>  <path>  <value>  <count>   # justification
#
# The key is (option, path, value) and the count must match EXACTLY. Any site not listed here fails
# the build; so does raising a listed value, or adding a second site at the same value to a listed
# file. This is a PROHIBITION with named exceptions, not a budget.
#
# ⚠ THIS LIST IS A LAST RESORT. It is not a place to record that something is slow. Hand-written Lean
# in this repo carries ZERO `maxHeartbeats`; every entry below is a generated definition or a measured
# structural case, and each states its floor bracket and its mechanism.
#
# Before adding an entry, read docs/agents/perf-findings.md §1 — extract over OPAQUE arguments, and
# check what the extraction can still see. Then meet the bar in §7: a measured floor bracket from a
# real ladder, a named mechanism, at least one attempted fix with its measured result, and a reason the
# cause cannot be moved (not merely that a first attempt did not move it). If the site is generated,
# fix the emitter in `update_extracted.py` instead — its blanket emission has repeatedly proven one to
# two orders of magnitude over what any definition actually needed.
#
# For calibration: upstream Clean has ZERO `maxHeartbeats` in 44,603 lines and 4 `maxRecDepth` sites,
# all in constant tables, capped at 2048, none in a proof.
#
# RE-MEASURED at Lean v4.32.2 (2026-08-06, the 4.31 -> 4.32.2 + Sail v4 -> v5 migration). Every one of
# the 11 sites was re-tested by STRIPPING its option and re-elaborating: all six files still fail
# without them, so no entry has become unnecessary. (That check matters because this gate is exact set
# equality — a site the toolchain no longer needs FAILS the build until its line is deleted.)
#

# generator, never by editing the file.
